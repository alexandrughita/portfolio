Case Study · Marketplace Platform

approape.ro

A location-based listings platform for the Romanian adult market: 2,000+ profiles across 100+ cities, a map and list browse, profile pages, ratings, private albums and a creator feed. Built on React and Firebase, with every important page pre-rendered for search engines.

View Live

The Challenge / why this exists

The Problem

  • Existing Romanian listing sites are dated, slow on mobile and full of duplicate or fake profiles
  • A single-page React app is close to invisible to search engines, and organic search is the main way people find this kind of site
  • Thousands of profile pages change all the time, and a fully static site goes stale the moment someone edits one
  • Visitors need a way to judge trust (verification, ratings) without the platform becoming a target for fake reviews

The Solution

  • A mobile-first PWA with map and list browse, city, service and seasonal landing pages
  • Build-time static generation for every profile and city page, with a shared SEO manifest so each page's head is defined only once
  • Edge middleware that serves a live render only for the profiles edited since the last build
  • Ratings that only engaged visitors can leave, aggregated server-side so nobody can forge a score

Tech Stack / what powers it

A React SPA on Vercel backed by Firebase, with a build pipeline that turns one Firestore snapshot into sitemaps, structured data and a few thousand crawlable HTML pages.

Key Features / what it does

Crawlable City Pages

Each city with enough listings gets a pre-rendered page with real profile cards, breadcrumb, FAQ and ItemList schema. Cities below the threshold are noindexed and left out of the sitemap, so thin pages never get indexed.

Fresh Static Profiles

Profile pages are static files, so they load instantly. The edge middleware keeps a list of profiles edited since the build, refreshed every minute, and serves only those from a live renderer. Every other request gets the static file.

Tamper-Proof Ratings

A 1-10 rating with three optional dimensions. Only visitors who actually made contact can rate. A Cloud Function recomputes the aggregate and enforces a daily cap, so the score can't be forged from the client.

"Top Girls" Ranking

One scoring module ranks profiles by ratings, completeness, verification, referrals and activity. The same module drives the homepage row, the map's z-order and an owner-only breakdown that shows each person how to climb the ranking.

Private Albums & Feed

Creators publish a feed and a private album. Access requests go through an approve/reject flow, and the Firestore rules are the only gatekeeper: the UI just attempts the read.

Video Verification

In-browser face-landmark detection asks the person to turn their head, measured from the nose tip relative to both eyes so the check works at any distance from the camera.

Consent-Free Contact Analytics

A first-party log of phone, WhatsApp and Telegram taps, tagged with traffic source. It stores no IP, user agent or client storage, so it doesn't need cookie consent and counts the contacts GA4 misses.

SEO Audit in CI

A build step compares every generated page against the SEO manifest and the sitemaps. It flags duplicate titles, missing schema, broken internal links, orphan pages and any head that drifted from its definition.

Admin & Moderation

A paginated admin dashboard for profiles, reports, ratings, feedback and contact analytics, with an owner dashboard rebuilt as a scored checklist of steps to complete a profile.

Architecture / how it works

Every build reads Firestore once and writes a data snapshot. Every generator (sitemaps, landing pages, profile pages, structured data) reads from that snapshot, so no two pages can disagree about a profile.
